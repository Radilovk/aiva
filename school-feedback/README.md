# Платформа за обратна връзка за училищата – референтна реализация

Анонимна обратна връзка от родители и ученици → оценки по 10 измерения (0–100) → индекс, интервали и категории за клас, училище, регион, система и (поверително) учител → API и MCP сървър за анализ с AI модел.

Само стандартна библиотека на Python 3.10+. Няма външни зависимости.

## Файлове

| Файл | Какво е |
| --- | --- |
| `build_questionnaire.py` | Източникът на въпросната банка. `python build_questionnaire.py` → `questionnaire.json` |
| `questionnaire.json` | 77 въпроса, скали, условия, роли, класове, измерения, тегла, норми, прагове (версия 1.0.1) |
| `render_bank.py` → `question_bank.md` | Въпросната банка като четим документ |
| `engine.py` | Динамичен поток, оценяване, качество, агрегиране, емпиричен Бейс, bootstrap, категории, справедливост, симулация |
| `test_engine.py` | 25 теста: `python -m unittest -v test_engine` |
| `api.py` | HTTP API: кодове, анкета, изчисляване, резултати с обхвати. Демо: `python api.py --demo` |
| `openapi.yaml` | Спецификация на API-то |
| `ai_tools.json` | 8 инструмента за AI модел (JSON Schema) |
| `mcp_server.py` | MCP сървър (stdio) върху API-то – за Claude и други MCP клиенти |
| `ai_report.py` | Автоматичен AI отчет през Anthropic Messages API с инструменти (`--dry-run` без ключ) |

## Бърз старт

```bash
python -m unittest -v test_engine          # тестове
python engine.py                           # симулация: корелация между истинско качество и индекс
python api.py --demo --port 8080           # API с 2 симулирани вълни и демо ключове
curl "http://127.0.0.1:8080/v1/units?level=school"
curl -H "X-API-Key: demo-school" "http://127.0.0.1:8080/v1/units?level=teacher"
```

При `--demo` в конзолата се отпечатват и готови кодове за анкетата (клас 6 и клас 4).

Демо ключове: `demo-public`, `demo-researcher`, `demo-school` (училище R1-S1), `demo-teacher` (учител R1-S1-T1), `demo-admin`.

### Анкета през API

```bash
# 1. администратор издава кодове за клас (връщат се веднъж; пазят се само хешове)
curl -X POST -H "X-API-Key: demo-admin" localhost:8080/v1/codes -d '{"wave":"2027-spring","class_id":"S1-2A","school_id":"S1","region_id":"R1","grade":2,"n_parent":24,"class_size":24,"roster":[{"teacher_id":"S1-T1","name":"г-жа Иванова","is_class_teacher":true}]}'
# 2. родител отваря анкетата с кода → роля, клас, учители, въпроси
curl -X POST localhost:8080/v1/session -d '{"code":"ABCD-1234-EF56"}'
# 3. при всеки отговор клиентът пита за видимите въпроси (разклонения)
curl -X POST localhost:8080/v1/flow -d '{"code":"ABCD-1234-EF56","answers":{"PR04":2}}'
# 4. изпращане (кодът става използван)
curl -X POST localhost:8080/v1/responses -d '{"code":"ABCD-1234-EF56","duration_s":420,"answers":{...},"teacher_answers":{"S1-T1":{"TC01":4}}}'
# 5. изчисляване на вълната
curl -X POST -H "X-API-Key: demo-admin" localhost:8080/v1/waves/2027-spring/compute
```

## Продукция: Cloudflare Worker + D1

Работещата версия е в основния Worker на репото (`aiva`), под `/api/sf`, с база D1 и сайт в `frontend/school/`.
Тази папка остава референтната реализация и източникът на въпросната банка.

| Какво | Къде |
| --- | --- |
| Движок (TypeScript порт на `engine.py`) | `workers/src/school/engine.ts` – чете директно `school-feedback/questionnaire.json` |
| API, D1 таблици (`sf_*`, създават се сами), обхвати на ключовете | `workers/src/school/routes.ts` |
| Начална страница, анкета, резултати, администрация | `frontend/school/` (`index.html`, `survey.html`, `results.html`, `admin.html`) |
| Движокът за браузъра (генериран, в git) | `frontend/school/lib/sf-engine.js` ← `node scripts/build-school-engine.mjs` |
| Проверка на съответствието TS ↔ Python и на генерирания файл | `node scripts/school-parity.mjs` |

Адреси след deploy: `https://aiva.radilov-k.workers.dev/school/` и през GitHub Pages
`https://ai-kasy.online/frontend/school/` (страниците викат API-то на Worker-а).

**Безплатният план на Cloudflare стига.** Никоя заявка към Worker-а не изчислява вълна: всяка е под ~3 ms CPU
(лимитът е 10 ms). Тежката статистика (bootstrap интервали, места, свиване към средното) се пуска от
`admin.html` в браузъра на оператора със същия движок: конзолата изтегля числовите отговори на страници по 250,
изчислява вълната (~1–2 s) и качва готовите редове. Списъците се връщат с една SQL заявка, без да се разчита JSON.
Свободният текст се изчиства и свежда до теми още при изпращане и не напуска сървъра; към конзолата излизат само
числовите отговори – същите данни, до които операторът и без това има достъп в D1. Лимитът за грешни кодове е в D1,
не в KV (безплатният KV има 1 000 записа на ден и се ползва и от KASY).

Еднократно (собственикът): `wrangler secret put SF_ADMIN_KEY` – дълъг случаен низ. С него се влиза в
`admin.html`: вълни, класове и кодове (листчета за печат), изчисляване, ключове за директори/учители/изследователи,
демо данни.

Анкетата: по един въпрос на екран, автоматично „напред“ при избор, „Не знам“ отделено встрани, клавиши 1–9 на
компютър, бутонът „назад“ на телефона връща към предишния въпрос, чернова само в текущия раздел, граматичен род
според отговора на ученика („напрегнат/а“ → „напрегната“), детска форма с големи емотикони, съгласие от родител
до VII клас, пробен режим без запис. Без външни шрифтове и заявки.

## Какво е прототип

* Данните в `api.py` са в паметта – за реална употреба: база данни, HTTPS, ограничение на заявките, журнал.
* Въпросите не са валидирани с реални хора; параметрите (норми, тегла, прагове) се калибрират след пилот.
* Тематичният анализ на свободния текст е речник с ключови думи; може да се замени с класификатор,
  който работи върху вече изчистения текст.
* Правният модел (кой оперира, основание за учителския модул, съгласие за деца под 14 г.) изисква юрист.
